# Database

## Storage

SQLite is stored at `data/portfolio.db` by default. `DatabaseManager.initialize()` creates the current tables if they do not exist.

## Schema

| Table | Purpose | Key columns |
| --- | --- | --- |
| `schema_version` | Records the initialized schema version. | `version` (primary key) |
| `watchlist` | Reserved watchlist storage. | `symbol` (primary key) |
| `market_prices` | Market snapshot rows written on each run. | `id` (primary key), `symbol`, `trade_date` |
| `portfolio` | Reserved portfolio storage. | `symbol` (primary key) |
| `recommendations` | Recommendation snapshot rows written on each run. | `id` (primary key), `symbol`, `trade_date` |
| `market_summary` | Reserved summary storage. | `trade_date` (primary key) |

## Current writes

For each `PortfolioResult`, `main.py` calls `DatabaseManager.save_market_snapshot()`.

The method writes:

- one `market_prices` row: symbol, current price, previous close, and day-change percentage;
- one `recommendations` row: symbol, buy score, and recommendation action.

`trade_date` is generated by SQLite using `DATE('now')`. Each method call commits its inserts before closing the connection.

## Operational notes

- The current schema records a snapshot on every application run; it does not upsert same-day rows.
- `watchlist`, `portfolio`, and `market_summary` are initialized but are not populated by the current batch path.
- Database files are intentionally ignored by Git. Do not commit `data/*.db`.
- Preserve existing data before making any schema or migration change.

## Local inspection

Use a local SQLite client, or Python's built-in shell:

```powershell
.\.venv\Scripts\python.exe -m sqlite3 data\portfolio.db
```

Example queries:

```sql
SELECT symbol, buy_score, recommendation
FROM recommendations
ORDER BY id DESC
LIMIT 20;

SELECT symbol, live_price, previous_close, day_change
FROM market_prices
ORDER BY id DESC
LIMIT 20;
```
